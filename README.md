# Cardboard Complex intro

Landing page opener and room navigation for Cardboard Complex. Built as plain HTML files driven by GSAP so every intro can be opened directly, compared side by side, and dropped on any static host.

- `docs/BRIEF.md` is the creative brief. Read it first.
- `CLAUDE.md` tells Claude Code how to work in this repo.
- `docs/NOTES.md` is the working log, newest entry at the top.
- `docs/PROMPTS.md` has starter prompts. `docs/PROMPT-PACK.md` has the image regeneration plan and prompts for a consistent walk-in sequence.
- `docs/type-specimen.html` shows the three candidate type systems (A, B, C) on the real copy. B is the current favorite; the intros keep the reference page fonts until a decision is made.

## What is in the repo

```
intros/01-door-reveal.html       roll-up door opens, camera pushes into the room
intros/02-walk-in-reveal.html    street establishing shot, dolly to the door, then the 01 reveal
intros/03-video-intro.html       plays the rendered MP4 or WebM and hands off to the room
intros/index.html                picker page that links every intro
assets/img/                      cropped plates the intros use
assets/img/2x/                   2x upscales of the walk-in frames (stopgap)
assets/logo/                     flat wordmarks for systems A, B and C (SVG and PNG)
assets/source/                   Steve's originals, never edit
reference/                       current live landing page and flyers, read-only reference
scripts/render-video.js          renders an intro's timeline to MP4 and WebM
scripts/make-wordmark.py         builds the wordmark SVGs from local font files
scripts/split-mock.py            splits Steve's 4-up door mock into single frames
video/out/                       rendered MP4 and WebM (landscape and portrait), tracked in git
```

## Run it locally

No build step. Open `intros/index.html` in a browser, or serve the folder so fonts and paths behave exactly as they will online:

```
npm install
npm run serve
```

Then visit `http://localhost:3000/intros/`. If you would rather not use Node for serving, `npm run serve:py` starts Python's server on port 8765, which is also the port the render script expects.

## Render the video

`scripts/render-video.js` seeks the intro's GSAP timeline frame by frame in headless Chromium, screenshots each frame, and encodes with ffmpeg. It writes `video/out/02-walk-in-reveal-{landscape,portrait}.{mp4,webm}` at 1920x1080 and 1080x1920.

Requirements:

- `npm install` (installs Playwright and the local GSAP copy).
- Chromium for Playwright: `npx playwright install chromium`, or point `CHROME_PATH` at an existing Chrome or Edge executable.
- `ffmpeg` on your PATH.
- A static server on port 8765 serving the repo root. In a second terminal run `npm run serve:py` (or `python -m http.server 8765`).

Then:

```
npm run render
```

That runs `node scripts/render-video.js intros/02-walk-in-reveal.html 30`. The first argument is the intro to render, the second is the frame rate. The intro must support `?render`, which builds the timeline paused and exposes it as `window.__tl`; 02 does.

Environment variables:

- `CHROME_PATH`: path to a Chrome, Chromium or Edge executable. Optional; without it Playwright uses its own Chromium.
- `GSAP_LOCAL`: path to a local `gsap.min.js`, for example `node_modules/gsap/dist/gsap.min.js`. Optional; set it when cdnjs is unreachable and the script will serve that file in place of the CDN request.

Intermediate frames land in `video/frames/`, which is ignored by git.

## Rebuild the wordmarks

`scripts/make-wordmark.py` outlines the wordmark text from the fontsource packages in `node_modules/@fontsource` and writes the SVGs to `assets/logo/` (the PNGs beside them were exported separately and are not regenerated by the script). It needs Python 3 with fontTools (`pip install fonttools`) and the fontsource packages, which `npm install` provides.

```
npm run wordmarks
```
